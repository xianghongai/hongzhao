# 鸿爪

> 泥上偶然留指爪，鸿飞那复计东西。（苏轼《和子由渑池怀旧》）

[![Ask DeepWiki](https://deepwiki.com/badge.svg)](https://deepwiki.com/xianghongai/hongzhao)

在浏览器里完成的日常小工具。不上传、不留存、不追踪：输入的内容只在页面里处理，关闭标签页即消失；访问过一次后，断网也能照常使用。

## 工具

- **二维码**：支持文本、网址、Wi-Fi、联系人（vCard）、邮件、短信、电话、位置、日程和两步验证（`otpauth://`）等格式，可下载 PNG 或 SVG。文本和网址可以开启“扫码后不直接打开链接”：手机扫码后先进入本站接收页显示原文，再手动复制，适合订阅地址这类只需复制、不该打开的内容。
- **链接传送**：把内容编码进链接的 `#` 之后，在另一台设备打开即可读取。可选 AES-256-GCM 加密，链接只携带密文，密钥以文本和二维码单独显示，传递方式自行决定。开启“固定密钥”后，多次生成共用同一把密钥；接收页是一个会话，密钥输入或扫描一次后，之后通过摄像头扫码、粘贴链接、粘贴或选择二维码截图、在同一标签页打开的内容都会自动解密。密钥和内容只保存在当前标签页的内存中。
  - 加密方式有两种。**随机密钥**：AES-256-GCM，随机 256 位密钥，需要把密钥交给接收方。**接收方公钥**：接收方先在接收页“解密”的“公钥”中生成公钥交给发送方，发送方经 X25519 密钥协商加 AES-256-GCM 加密，无需传递密钥。公钥二维码编码的是发送页链接，发送方用手机扫码即可打开发送页并自动填好公钥。私钥只在接收页内存中，所以要在该页面里粘贴链接或扫码接收；刷新前可以在对话框中查看并备份私钥，之后用“导入私钥”恢复。
- **2FA**：输入一个或多个 Base32 密钥或 `otpauth://` 链接，也可以选择、粘贴或拖入二维码截图导入，生成 TOTP 验证码，并可导出为二维码供手机验证器 App 扫描。截图只在本机识别，密钥只保存在当前标签页的内存中。

## 隐私承诺如何兑现

| 承诺   | 实现方式                                                                                                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 不上传 | 构建产物带有内容安全策略（CSP）`connect-src 'none'`，由浏览器阻止一切 fetch、XHR、WebSocket 和 beacon。链接传送的内容位于 URL 的 `#` 片段，浏览器不会把片段发送给服务器，接收页读取后立即将其从地址栏移除。Service Worker 会下载和更新本站自身的文件，这些请求不含任何输入内容 |
| 不留存 | 不使用 Cookie、localStorage、sessionStorage 或 IndexedDB，主题和语言偏好也不保存，手动选择的语言只写在网址参数 `?lang=` 里；离线缓存（Cache Storage）里只有本站的代码、样式、字体和图标                                                                                        |
| 不追踪 | 没有统计和第三方脚本；所有依赖从 npm 安装并随站点打包，不引用 CDN                                                                                                                                                                                                              |

验证方法：打开浏览器开发者工具的“网络”面板后使用任意工具，列表中不会出现新的请求。访问过一次后，断开网络也能继续使用。

链接传送的残余风险：浏览器会把打开过的完整链接记入历史记录，开启同步时还会上传。传送敏感内容时应开启加密，并让链接和密钥走不同的渠道。

## 界面语言

切换后所选语言写入网址参数 `?lang=`，刷新和书签都能保留。链接传送生成的链接不带语言参数，接收方按自己的浏览器语言显示。

文案放在 `src/locales/`，每种语言构建成一个独立的脚本文件，只在显示该语言时加载。没有放在 `public/` 里用 `fetch()` 读取，因为 CSP 的 `connect-src 'none'` 会拦截这类请求。

## 离线与安装

站点是 PWA。首次访问时，Service Worker 缓存全部页面、脚本、字体和图标，之后断开网络也能打开首页、所有工具和接收页（包括解密）。支持的浏览器会在页脚显示“安装到本机”，安装后以独立窗口运行。

发布新版本后，页面会提示“有新版本”，由使用者决定何时刷新。刷新会清空内存中的内容，包括已添加的两步验证密钥，因此不会自动刷新。

Service Worker 只能在安全上下文（HTTPS 或 `localhost`）中运行。通过 HTTP 局域网地址访问时没有离线缓存，其余功能不受影响。

## 链接格式

接收链接的形式为 `<站点根地址>r/#<信封>`。“内容”二维码只包含信封本身，不带网址。信封是一个查询串，只有两个参数，`alg` 取 JOSE（RFC 7518）注册的算法名：

| 场景       | 信封                 | `data` 内部依次为                |
| ---------- | -------------------- | -------------------------------- |
| 明文       | `data=…`             | 压缩标记与内容                   |
| 随机密钥   | `alg=A256GCM&data=…` | 随机数、密文与认证标签           |
| 接收方公钥 | `alg=ECDH-ES&data=…` | 临时公钥、随机数、密文与认证标签 |

- `ECDH-ES` 固定表示：每条消息生成临时 X25519 密钥对，与接收方公钥协商出共享密钥，经 HKDF-SHA256（以两把公钥为盐）派生出 AES-256-GCM 密钥。
- 两种加密方式都以 `alg` 的值作为附加认证数据。
- 内容在编码前按需用 deflate 压缩。
- 密钥一律是不带填充的 Base64URL（与 JWK 相同），不带任何前缀，包括随机密钥和 X25519 公钥、私钥；用途由输入的位置决定。
- 公钥链接的形式为 `<站点根地址>#/share?public_key=<公钥>`，参数位于 `#` 片段中，不会发送给服务器。

`r/` 路径、参数名（`alg`、`data`、`public_key`）以及 `alg` 各取值的含义都是公开契约，已发出的链接必须持续可用：新的加密方式只能新增 `alg` 取值，已有取值始终按原规则解码。

站点将来绑定自定义域名时，GitHub Pages 会把旧地址重定向到新域名并保留路径，浏览器在重定向时保留 `#` 片段，因此旧链接仍然有效。二维码容量检查按至少 80 个字符的站点前缀预留余量，更换为不超过该长度的域名后，原本放得下的内容依然放得下。

## 开发

需要 Node.js 24 和 pnpm，版本由 `mise.toml` 与 `package.json` 的 `packageManager` 字段管理。

```sh
pnpm install
pnpm dev          # 仅本机访问
pnpm dev:lan      # 同时监听局域网地址，供手机访问
```

| 命令                        | 作用                                                |
| --------------------------- | --------------------------------------------------- |
| `pnpm build`                | 构建站点到 `dist/`                                  |
| `pnpm preview:lan`          | 在局域网预览构建产物                                |
| `pnpm test`                 | 运行单元测试                                        |
| `pnpm check-types`          | 类型检查                                            |
| `pnpm lint` / `pnpm format` | 代码检查与格式化                                    |
| `pnpm locales:hant`         | 由简体中文文案重新生成繁体中文                      |
| `pnpm pwa:icons`            | 由 `public/favicon.svg` 重新生成 PWA 图标           |
| `pnpm pwa:icons:amber`      | 重新生成琥珀色底的图标物料（`public/brand/amber/`） |

局域网通常通过 HTTP 访问，不属于安全上下文，浏览器不提供 WebCrypto 和异步剪贴板 API。因此加密使用 `@noble/ciphers`，TOTP 使用 `otpauth`（基于 `@noble/hashes`），复制在非安全上下文下回退到 `execCommand`，除摄像头扫码外，所有功能在 HTTP 局域网地址下都可以正常使用；摄像头需要 HTTPS，此时扫码按钮显示为不可用。

通过 `localhost` 生成的中转或传送链接在其他设备上打不开，页面会给出提示；需要手机扫码时，应改用 `pnpm dev:lan` 输出的局域网地址打开页面。构建时设置 `VITE_SHARE_BASE` 可以固定链接指向的站点根地址。

## 技术栈

Vite、React、TypeScript、Tailwind CSS v4、shadcn/ui（Base UI）、Lucide、Motion。离线与安装使用 `vite-plugin-pwa`（Workbox）。多语言使用 i18next 与 react-i18next，繁体中文由 OpenCC（`opencc-js`）在开发时生成。二维码生成使用 `uqr`；识别优先使用浏览器原生的 `BarcodeDetector`，不可用时回退到纯 JavaScript 的 `jsQR`，不加载 WASM，因此不需要放宽 CSP。编码使用 `@scure/base` 和 `fflate`。
